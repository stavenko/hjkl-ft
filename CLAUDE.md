# Правила этого проекта

Короткий список того, на чём сессии спотыкаются раз за разом. Подробности — в
`docs/`; здесь только то, что надо знать ДО первого действия.

## Версия локальной базы растёт и никогда не падает

`DB_VERSION` (`frontend/src/services/db.rs`) — только вверх. **Не предупреждай об
откате сборки: откатываться некуда.** IndexedDB не откроет базу версией меньше
записанной в ней, так что старый код на новой базе не запустится вовсе, у всех
сразу. Это не риск, который взвешивают, — это несуществующий вариант.

Поломка в выложенной сборке чинится СЛЕДУЮЩЕЙ выкладкой вперёд, с новой версией и,
если надо переложить данные, с миграцией (`frontend/src/services/migrations/`).
Отменить смысл прошлой миграции — это новая миграция с бо́льшим номером, а не откат.

Новый пустой store миграции не требует: объявить в билдере, дописать в `ALL_STORES`,
поднять версию — `idb` создаст его сам.

Подробнее: `docs/deploy.md`, раздел «Версия локальной базы: только вперёд».

## Труба съедает код возврата

`cargo test | tail` возвращает код `tail`, а не теста. Упавший прогон через трубу
выглядит зелёным — на этом уже дважды выкладывали сломанное. Пиши в файл и печатай
код явно:

```
cargo test -p frontend --lib > /tmp/ut.log 2>&1; echo "КОД $?"; tail -3 /tmp/ut.log
```

Подробнее: `docs/testing.md`.
