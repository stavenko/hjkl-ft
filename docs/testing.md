# Как гонять проверки

Проверок в `scripts/` шесть десятков, и почти все — браузерные: поднимают
приложение и утверждают что-то про его поведение. Здесь то, что нужно знать до
первого запуска, и одно правило, которое стоит часа потерянного времени.

## Правило первое: вывод сохраняется в файл

**Никогда не пропускайте прогон через `| tail` или `| head`.**

Итог печатается ПЕРЕД подробностями по упавшим проверкам — так удобнее читать с
экрана. Значит `| tail -60` срезает ровно итог и оставляет хвост подробностей, а
`| head` — наоборот. Часовой прогон при этом придётся повторить целиком.

Прогон регрессии пишет лог сам:

```
node scripts/run-regression.mjs          # → regression-local.log
DEV=1 node scripts/run-regression.mjs    # → regression-dev.log
```

В логе — полный вывод КАЖДОЙ проверки, не только упавшей. На экран идёт короткая
сводка. Отдельную проверку перенаправляйте руками:

```
node scripts/check-curator-flow.mjs > /tmp/curator.log 2>&1; echo "код $?"
```

Дальше по файлу работайте `grep`, а не чтением целиком: в логе десятки тысяч
строк, и открывать его весь — это просто время и деньги, потраченные на прокрутку.

```
grep -E "^(OK|FAIL)" regression-local.log   # сводка
sed -n '/═══ check-fiber-week/,/═══/p' regression-local.log   # одна проверка
```

Это же относится к долгим прогонам вообще: запускайте в фоне с перенаправлением в
файл, а не держите вывод в терминале.

## Как проверки устроены

Две породы, и различать их важно.

**Со своим сервером** — `check-curator-flow`, `check-fresh-bind-unbind`,
`check-planka-sync`, `check-diary-week`. Поднимают локальный сервер сами
(`scripts/lib/devserver.mjs`), запускаются просто:

```
node scripts/check-curator-flow.mjs
DEV=1 node scripts/check-curator-flow.mjs   # по ВЫКАЧЕННОМУ приложению
```

**Накопленные** — остальные. Ждут адрес в `FE` и браузер по умолчанию. Их гоняет
`run-regression.mjs`, который подставляет им общий сервер и установленный
chromium.

## Почему нужен локальный сервер

В части окружений (в том числе в контейнере, где это писалось) **браузер наружу
не ходит, а node ходит**. Поэтому `devserver.mjs` раздаёт статику и проксирует
обращения приложения к живым dev-воркерам: браузер знает только `127.0.0.1`, а до
воркеров дотягивается node.

`DEV=1` меняет источник статики: файлы берутся с выкаченного приложения, а не из
локального `dist`. Тогда проверка захватывает и саму выкладку — заголовки,
`_worker.js`, пути к картинкам. Адреса воркеров подменяются в обоих случаях:
настоящие приложению отдать нельзя, оно до них не дойдёт.

## Что этим НЕ покрыто

Стоит помнить, чтобы не обещать лишнего:

- **Service worker выключен** во всех прогонах — путь обновления PWA не
  проверяется.
- **CORS живого происхождения** не проверяется: запросы идут через локальный
  прокси. Именно этот класс ошибки однажды ловился руками, запросом `OPTIONS`.
- **Апгрейд базы** — проверки начинают с чистой базы, а не со старой версии.

## Стенд и его ограничения

`scripts/harness.mjs` сеет пользователя с НЕНАСТОЯЩИМ токеном: приложение с ним
не сможет ни синхронизироваться, ни спросить сервер о кураторе. Поэтому стенд
сразу проставляет `support_current_peer` — иначе недельный пересчёт планок не
запускается вовсе: он ждёт ответа, кто ведёт этого человека.

Проверкам, которым нужен настоящий счёт, его выдаёт `scripts/lib/devuser.mjs`
(`createPaidUser`, `mintToken`) — тем же секретом, что у dev-воркеров. Это и есть
«обход авторизации»: паскей проверяет личность, а проверкам нужна не она, а всё,
что происходит после входа.

## Когда проверка упала

Прежде чем чинить приложение — убедитесь, что упала не сама проверка:

1. **Может ли она вообще работать здесь?** Часть скриптов ходит в админку на
   другом происхождении или вшила живой адрес. Такие честно называются в
   пропусках `run-regression.mjs`, с причиной у каждого.
2. **Это уже было?** Соберите `main` в отдельном дереве и прогоните тот же
   список: разница двух логов и есть то, что сломано вами.

   ```
   git worktree add /tmp/main-tree origin/main
   cd /tmp/main-tree/frontend && trunk build --release
   FE_DIST=/tmp/main-tree/frontend/dist node scripts/run-regression.mjs
   ```
3. **Что говорит само приложение?** Оно называет причины вслух: «пересчёта нет —
   адресат ещё не известен», «планка ещё не поставлена». Ловите их через
   `page.on('console')` — это быстрее любого разглядывания кода.
